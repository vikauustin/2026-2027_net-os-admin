# Цель работы

Получение навыков по управлению системным временем и настройке синхронизации времени.

# Задание

1. Изучите команды по настройке параметров времени (см. раздел 12.4.1).
2. Настройте сервер в качестве сервера синхронизации времени для локальной сети
(см. раздел 12.4.2).
3. Напишите скрипты для Vagrant, фиксирующие действия по установке и настройке
NTP-сервера и клиента (см. раздел 12.4.3)

# Теоретическое введение

В Unix/Linux системах используется несколько служб для настройки и синхронизации времени.
За синхронизацию времени на узлах сети отвечает протокол NTP (Network Time Protocol). В его основе лежит специальный алгоритм согласования данных (алгоритм Марзулло), используемый при выборе источников оценки точного времени.

# Выполнение лабораторной работы
 
На сервере выведены параметры времени командой `timedatectl`: часовой пояс UTC, служба NTP активна, но системные часы не синхронизированы (System clock synchronized: no). Затем просмотрено системное время командой `date`, аппаратное время командой `hwclock`, а также выведено время в заданном формате, где час и минуты совпадают с системным временем (рис. [-@fig:001]).
 
![Параметры времени на сервере: timedatectl, date и hwclock](image/1.jpg){#fig:001 width=70%}
 
На сервере команда `chronyc sources` не выводит ни одной строки: внешних источников времени у сервера нет (рис. [-@fig:002]).
 
![Список источников времени на сервере до настройки](image/2.jpg){#fig:002 width=70%}
 
На клиенте те же команды показывают тот же часовой пояс UTC и время, а системные часы синхронизированы (System clock synchronized: yes). Команда `chronyc sources` выводит четыре внешних источника, строка со звёздочкой отмечает сервер 168.119.211.223, с которым клиент синхронизирован сейчас. Символ `^` означает, что источник является сервером, знак `+` у 94.130.35.4 — приемлемый источник, а знак `-` у остальных — источники, которые не используются для выбора времени. Страта источников 2–3, интервал опроса 64 секунды (значение Poll 6), а значение Reach 377 или близкое означает, что последние опросы успешны (рис. [-@fig:003]).
 
![Параметры времени и источники времени на клиенте до настройки](image/3.jpg){#fig:003 width=70%}
 
На сервере в файл `/etc/chrony.conf` добавлены строки `allow 192.168.0.0/16`, разрешающая синхронизацию клиентам локальной сети, и `local stratum 10`, чтобы сервер оставался источником времени, даже если внешние серверы недоступны. После перезапуска chronyd в межсетевом экране разрешена служба ntp и правила перезагружены (рис. [-@fig:004]).
 
![Настройка сервера как источника времени для локальной сети и межсетевого экрана](image/4.jpg){#fig:004 width=70%}
 
На клиенте в файле `/etc/chrony.conf` закомментированы строки с директивами pool и server, добавлена строка `server server.vvustinova.net iburst`, и служба chronyd перезапущена. Команда grep показывает, что остался единственный источник — сервер локальной сети (рис. [-@fig:005]).
 
![Настройка клиента: единственный источник времени — server.vvustinova.net](image/5.jpg){#fig:005 width=70%}
 
На сервере `chronyc sources` по-прежнему пуст, а `chronyc tracking` показывает страту 10 и идентификатор источника 7F7F0101, то есть сервер использует собственные локальные часы. Смещение и задержки равны нулю, так как сравнивать время не с чем, статус синхронизации Normal. Затем в каталоге provision создан каталог ntp/etc и в него скопирован файл `chrony.conf` (рис. [-@fig:006]).
 
![Информация о синхронизации на сервере и копирование chrony.conf в каталог provision](image/6.jpg){#fig:006 width=70%}
 
На клиенте единственным источником стал server.vvustinova.net со знаком `*`, то есть клиент синхронизирован с нашим сервером (страта сервера 10, Reach 17). В выводе `chronyc tracking` страта клиента равна 11, то есть на единицу больше, чем у сервера, идентификатор опорного источника C0A80101 соответствует адресу 192.168.1.1. Системное время отличается от времени NTP примерно на 1 мс, последнее смещение составляет около 0,066 с, интервал обновления 64,7 с (рис. [-@fig:007]).
 
![Источники времени и подробная информация о синхронизации на клиенте](image/7.jpg){#fig:007 width=70%}
 
В каталоге provision на сервере создан скрипт `ntp.sh`: он устанавливает chrony, копирует конфигурацию, восстанавливает контексты SELinux, разрешает службу ntp в межсетевом экране и перезапускает chronyd (рис. [-@fig:008]).
 
![Скрипт ntp.sh виртуальной машины server](image/8.jpg){#fig:008 width=70%}
 
На клиенте создан скрипт `ntp.sh`, который копирует конфигурацию chrony, восстанавливает контексты SELinux и перезапускает chronyd (рис. [-@fig:009]).
 
![Скрипт ntp.sh виртуальной машины client](image/9.jpg){#fig:009 width=70%}
 
В Vagrantfile в конфигурацию сервера добавлена запись provision «server ntp» (рис. [-@fig:010]).

# Выводы
 
В ходе работы получены навыки по управлению системным временем и настройке синхронизации времени. Изучены команды date, hwclock и timedatectl, а также вывод `chronyc sources` и `chronyc tracking`. Сервер настроен как источник времени для локальной сети, а клиент переведён на синхронизацию с этим сервером и получил страту на единицу ниже. Действия по настройке сервера и клиента зафиксированы в скриптах `ntp.sh`, подключённых в Vagrantfile.
 
# Ответы на контрольные вопросы
 
1. Почему важна точная синхронизация времени для служб баз данных? — Базы данных используют время в журналах транзакций, метках изменений, репликации и разрешении конфликтов. Если часы узлов расходятся, нарушается порядок операций, а данные на разных серверах могут оказаться несогласованными. 

2. Почему служба проверки подлинности Kerberos сильно зависит от правильной синхронизации времени? — Билеты Kerberos содержат метки времени и ограниченный срок действия, чтобы нельзя было повторно использовать перехваченный билет. Если часы клиента и сервера расходятся больше допустимого (по умолчанию примерно на 5 минут), аутентификация завершается отказом.

3. Какая служба используется по умолчанию для синхронизации времени на RHEL 7? — Служба chronyd (пакет chrony).

4. Какова страта по умолчанию для локальных часов? — Страта 10, она задаётся директивой `local stratum 10`.

5. Какой порт брандмауэра должен быть открыт, если вы настраиваете свой сервер как одноранговый узел NTP? — Порт 123/UDP, то есть служба ntp в firewalld.

6. Какую строку вам нужно включить в конфигурационный файл chrony, если вы хотите быть сервером времени, даже если внешние серверы NTP недоступны? — Строку `local stratum 10`.

7. Какую страту имеет хост, если нет текущей синхронизации времени NTP? — Страту 16: в NTP это значение означает, что часы не синхронизированы.

8. Какую команду вы бы использовали на сервере с chrony, чтобы узнать, с какими серверами он синхронизируется? — Команду `chronyc sources`.

9. Как вы можете получить подробную статистику текущих настроек времени для процесса chrony вашего сервера? — Командой `chronyc tracking`, а статистику по источникам времени выводит команда `chronyc sourcestats`.
