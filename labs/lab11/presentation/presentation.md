# Вводная часть
 
## Цель работы
 
Приобретение практических навыков по настройке удалённого доступа к серверу с помощью SSH.
 
## Задание
 
1. Настроить запрет удалённого доступа на сервер по SSH для пользователя root.
2. Настроить разрешение удалённого доступа к серверу по SSH только для пользователей группы vagrant и своего пользователя.
3. Настроить удалённый доступ к серверу по SSH через порт 2022.
4. Настроить удалённый доступ к серверу по SSH по ключу.
5. Организовать SSH-туннель с клиента на сервер, перенаправив локальное соединение с TCP-порта 80 на порт 8080.
6. Используя удалённое SSH-соединение, выполнить с клиента несколько команд на сервере.
7. Используя удалённое SSH-соединение, запустить с клиента графическое приложение на сервере.
8. Написать скрипт для Vagrant, фиксирующий действия по настройке SSH-сервера во внутреннем окружении виртуальной машины server, и внести соответствующие изменения в Vagrantfile.
# Выполнение лабораторной работы
 
## Вход под пользователем root
 
С клиента выполнена попытка входа по SSH под пользователем root. После ввода пароля сервер отвечает Permission denied и завершает соединение.
 
![Попытка входа на сервер по SSH под пользователем root](image/1.jpg){#fig:001 height=55%}
 
## Запрет входа root
 
На сервере задан пароль root, в конфигурацию sshd добавлена строка `PermitRootLogin no`. Файл проверен командой `sshd -t`, sshd перезапущен.
 
![Запрет входа root по SSH в конфигурации sshd](image/2.jpg){#fig:002 height=55%}
 
## Вход пользователя до ограничений
 
Вход под своим пользователем выполнен с третьей попытки (первые два пароля введены неверно), так как ограничений на пользователей ещё нет.
 
![Вход под своим пользователем до ограничения списка пользователей](image/3.jpg){#fig:003 height=55%}
 
## Список AllowUsers
 
В конфигурацию sshd добавлена строка `AllowUsers vagrant`, разрешающая вход только пользователю vagrant. Файл проверен, sshd перезапущен.
 
![Добавление строки AllowUsers vagrant в конфигурацию sshd](image/5.jpg){#fig:005 height=55%}
 
## Отказ пользователю vvustinova
 
Попытка входа под пользователем vvustinova завершается отказом Permission denied, так как его нет в списке AllowUsers.
 
![Отказ в доступе пользователю vvustinova после ограничения списка пользователей](image/4.jpg){#fig:004 height=55%}
 
## Добавление своего пользователя
 
Список разрешённых пользователей расширен: `AllowUsers vagrant vvustinova`. Результат проверен командой grep, sshd перезапущен.
 
![Добавление своего пользователя в список AllowUsers](image/6.jpg){#fig:006 height=55%}
 
## Успешный вход
 
После изменения списка AllowUsers вход под пользователем vvustinova выполнен успешно.
 
![Успешный вход пользователя vvustinova после изменения списка AllowUsers](image/7.jpg){#fig:007 height=55%}
 
## Порт 2022 и ошибка привязки
 
В конфигурацию добавлены строки `Port 22` и `Port 2022`. После перезапуска служба активна, но в журнале видна ошибка привязки к порту 2022: для него в SELinux не задана метка SSH.
 
![Добавление порта 2022 и ошибка привязки sshd к порту](image/8.jpg){#fig:008 height=55%}
 
## SELinux и межсетевой экран
 
Для порта 2022 задана метка ssh_port_t в SELinux, порт открыт в межсетевом экране (в текущей и постоянной конфигурации). После перезапуска sshd запускается без ошибок.
 
![Настройка SELinux и межсетевого экрана для порта 2022](image/9.jpg){#fig:009 height=55%}
 
## Подключение через порты 22 и 2022
 
Выполнено подключение к серверу через порт по умолчанию и командой `ssh -p2022` через порт 2022. В обоих случаях вход выполнен, `sudo -i` даёт доступ root.
 
![Подключение к серверу через порт 22 и через порт 2022](image/10.jpg){#fig:010 height=55%}
 
## Вход по ключу
 
На клиенте сформирована пара ключей SSH, открытый ключ скопирован на сервер командой `ssh-copy-id`. После этого вход выполняется без ввода пароля.
 
![Копирование открытого ключа на сервер и вход по ключу](image/11.jpg){#fig:011 height=55%}
 
## SSH-туннель
 
Организован туннель с локального порта 8080 на порт 80 сервера. В выводе `lsof | grep TCP` виден процесс ssh, прослушивающий порт 8080
(webcache) по IPv4 и IPv6.
 
![Вывод lsof после создания SSH-туннеля](image/12.jpg){#fig:012 height=55%}
 
## Проверка туннеля в браузере
 
В браузере по адресу localhost:8080 открывается страница с приветствием «Welcome to the server.vvustinova.net server.», туннель работает.
 
![Страница сервера, открытая через SSH-туннель](image/13.jpg){#fig:013 height=55%}

Выполнены команды на сервере: `hostname` показывает имя узла, `ls -Al` — список файлов домашнего каталога. Просмотрена почта: в ящике четыре сообщения, одно новое.
 
![Выполнение команд на сервере через SSH](image/14.jpg){#fig:014 height=55%}
 
## X11Forwarding
 
В основном файле sshd_config параметр X11Forwarding отключён, в 50-redhat.conf включён. Добавлена строка `X11Forwarding yes` и запущена установка пакетов xorg-x11-xauth и firefox.
 
![Разрешение X11Forwarding и установка пакетов для запуска Firefox](image/15.jpg){#fig:015 height=55%}
 
## Графическое приложение через SSH
 
Браузер Firefox, запущенный на сервере, отображается на клиенте.
 
![Окно Firefox, запущенного на сервере и показанного на клиенте](image/16.jpg){#fig:016 height=55%}
 
## Скрипт ssh.sh
 
Скрипт копирует конфигурацию sshd, восстанавливает контексты SELinux, открывает порт 2022 в межсетевом экране, добавляет порт в SELinux и перезапускает sshd.
 
![Скрипт ssh.sh виртуальной машины server](image/17.jpg){#fig:017 height=55%}
 
## Vagrantfile
 
В Vagrantfile в конфигурацию сервера добавлена запись provision «server ssh».

# Заключение
 
## Выводы
 
В ходе работы получены практические навыки по настройке удалённого доступа к серверу с помощью SSH. Запрещён вход root, доступ ограничен списком пользователей, настроена работа sshd через дополнительный порт 2022 с метками SELinux и правилами межсетевого экрана, а также вход по ключу. Создан SSH-туннель с локального порта 8080 на порт 80 сервера, через SSH выполнены команды и запущено графическое приложение. Действия по настройке сервера зафиксированы в скрипте `ssh.sh`, подключённом в Vagrantfile.
